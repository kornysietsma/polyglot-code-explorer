# Implementation plan: tooling & dependency refresh

Companion to [`spec.md`](./spec.md). The spec says *what and why*; this says *in what order,
and how we know each step worked*.

**Branch:** `tooling-refresh` off `master`
**Execution model:** one commit per step. Claude implements; Korny verifies at the numbered
**gates**. Claude stops at each gate and asks rather than pressing on.

## 1. Corrections to the spec

Four things found while planning that change the spec's assumptions. The spec is otherwise accurate.

### 1.1 The app on `master` cannot load any local data file 🔴

`SUPPORTED_FILE_VERSION` is `"1.0.5"` (bumped in `763f13f`, Apr 2026). The check at
`Loader.tsx:34` is `semver.satisfies(data.version, SUPPORTED_FILE_VERSION)` — a bare version as a
range means **exact match**. Every file in `public/data/` was 1.0.4 or older, including the tracked
`default.json`. Nothing loaded.

`763f13f` changed *only* the constant in `polyglot_data.types.ts` — no type or shape change — so
the 1.0.4 payload format is still structurally valid. Korny has since generated a genuine 1.0.5
`omf.json`. Step 0.1 bumps `default.json` to match.

### 1.2 `circlePack` vs `nestedCircles` is a real bug 🔴

The scanner now emits `layout.algorithm: "nestedCircles"` for the root node (`omf.json`); the
old format used `"circlePack"` (`default.json`). `NodeLayout.algorithm` is typed as bare `string`,
so nothing caught the rename. Two places read the old value:

| Site | Effect when it wrongly evaluates false |
|---|---|
| `BaseVisualization.tsx:110` | circle-pack background colour never applied |
| `Loader.tsx:65` → `metadata.topLevelCirclePacked` | **depth offsets wrong by one** at `Viz.tsx:84, 92, 123, 426` |

That second one is the serious one: `topLevelCirclePacked` shifts the nesting depth used for line
widths and nested colours — precisely the feature added in the two most recent commits
(`6371a3f` "added fourth nesting level", `763f13f` "fixed bug in deeply nested colours"). With
current scanner output, nesting styling is applied one level off.

Korny's call: **investigate and fix** (step 0.2), *before* baselines are captured, so the baselines
record corrected behaviour.

### 1.3 There are five `NumberPicker`s, not two

`6371a3f` added a fourth nesting level. `ColoursAndLinesControls.tsx` now has 5 `NumberPicker` +
5 `ColourPicker` pairs (1 default + 4 nesting levels). Repetitive, but 2.5× the swap surface.

### 1.4 Spec §9 open questions — resolved

- `@testing-library/user-event` — **unused**, drop it.
- `ts-unused-exports` — **unused**, no script references it, drop it.
- `data-theme` — `"dark" | "light"`, default `dark`, toggled by a button in `Controller.tsx:73-95`.
- `src/global.d.ts` is **entirely** dead (only the `*.module.css` declaration) — replace wholesale.
- `src/setupTests.ts` imports `@testing-library/jest-dom/extend-expect`, **a subpath removed in
  jest-dom v6+**. Must become `import "@testing-library/jest-dom/vitest"` (step 4.1).
- Circle-pack is **not** a UI mode — it's a per-node `layout.algorithm` in the data file.

## 2. Fixtures

Two data files, different jobs. Neither alone covers everything.

| File | Version | Size | git | coupling | root algorithm | Role |
|---|---|---|---|---|---|---|
| `public/data/default.json` | 1.0.4 → **1.0.5** (step 0.1) | 746 KB | ✅ 102/102 files, 3 users | ✅ 14 files | `circlePack` | **Committed regression fixture** + shipped default |
| `public/data/omf.json` | 1.0.5 | 3.9 MB | ✅ 1298/1739 files, 207 users | ❌ | `nestedCircles` | **Manual smoke test** — untracked, too big to commit |

`default.json` is the automated fixture: small, tracked, and the only file exercising coupling.
`omf.json` is the manual one: the only file in the *current* scanner format and the only one
exercising `nestedCircles` — which is exactly why step 0.2 needs it.

> **Follow-up, out of scope:** Korny wants `default.json` eventually regenerated by the current
> scanner using `nestedCircles`, since that is the fiddlier layout case. Tracked in §7.

### 2.1 Avoiding a duplicated 746 KB

The Playwright run needs a data file *plus* a pinned `_state.json` sidecar. Committing
`explorertest.json` as a second copy of `default.json` would duplicate 746 KB and let the two
drift apart. Instead:

- Commit **only** `tests/fixtures/explorertest_state.json` (small).
- `tests/global-setup.ts` copies `default.json` → `explorertest.json` beside it at run start, and
  copies the state fixture next to it. Both copies are gitignored.
- Tests run with `EXPLORER_DATA=explorertest`.

The fixture therefore tracks the shipped default automatically, and the state sidecar never
affects a normal `npm start`.

## 4. Technical design decisions

Beyond the spec, decided while planning.

**`process.env` is shimmed before it is replaced.** Step 2.1 stands Vite up *alongside* CRA using
`define: { "process.env.REACT_APP_VERSION": ... }`, so no source changes are needed to get Vite
running. Source moves to `__APP_VERSION__` / `import.meta.env.BASE_URL` in 2.3, after CRA is gone.
This makes the switchover independently verifiable at each half.

**Playwright's `webServer` command changes twice** — `REACT_APP_EXPLORER_DATA=explorertest yarn
start` (0.3) → `npm start` (1.1) → `EXPLORER_DATA=explorertest npm run dev` (2.3). Easy to forget;
called out in each step.

**React 19 and TypeScript 6 are separate steps** (3.1, 3.2). Both produce type errors; together
you cannot tell which upgrade caused what.

**Formatting is its own commit** (5.2), so Prettier 3's reflow never hides a real change.

**`preprocess.ts`'s `unitOfTime.StartOf` collapses to a literal.** `gatherTimescaleData` is called
from exactly one place (`Loader.tsx:54`) and always with `"week"`. Replace the moment type with a
narrow local union rather than reproducing moment's whole `StartOf` type. Pin
`startOfWeek(d, { weekStartsOn: 0 })` explicitly — moment's default is locale-dependent and
happens to be Sunday for `en`; don't leave that to chance.

**`humanizeDate`'s format is safe.** moment `"DD-MMM-YYYY"` → date-fns `"dd-MMM-yyyy"` produce
identical output (`05-Jan-2022`). Shot 7 covers it.

**Do not add `React.StrictMode`** (spec §3) — double-invoked effects would break `Viz.tsx`'s
imperative D3.

## 8. Rollback

Every step is one commit on `tooling-refresh`; `master` is untouched throughout. To abandon a step,
`git revert` it — no step depends on a later one. To abandon the project, delete the branch. The
only change with reach beyond the branch is the `public/data/` → `data/` move at 6.1, which touches
untracked local files; note the old path if you switch back to `master`.
